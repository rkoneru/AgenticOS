# Billing threat model

Scope: `services/billing`, the runtime emitter, the Stripe adapter. Assets: what each tenant is charged (integrity), tenant usage
data (confidentiality), provider credentials, revenue.

| #   | Threat                                                                                          | Mitigation                                                                                                                                                                                                                                     | Evidence                                                   | Residual                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| B1  | Usage forgery: a caller invents `model_call` or tool events to bill (or to under-bill) a tenant | Only the `ingest` scope can post run events; the service bills a result only if the same run log holds an ALLOW decision with the same `action_id`; keys derive from `run:<id>:<seq>`; a changed replay is a conflict; events carry no content | `emitters.test.ts`, `dev-server.test.ts`                   | A holder of an ingest token can still forge a coherent log for ITS tenant (NEEDS 806: signed events or mTLS) |
| B2  | Replay: re-sending events to double-bill                                                        | `UNIQUE (tenant_id, idempotency_key)` + payload hash; replays are no-ops                                                                                                                                                                       | ledger contract tests (memory and Postgres), property test | none known                                                                                                   |
| B3  | Idempotency-key collision across tenants                                                        | key unique per tenant; RLS scopes every lookup                                                                                                                                                                                                 | `scopes the idempotency key to the tenant` (mutated)       | none known                                                                                                   |
| B4  | Tenant spoof: a body or query names another tenant                                              | tenant is taken from the bearer token; a differing `tenant_id` is 403; a run whose `run_started.tenant_id` differs is refused                                                                                                                  | `dev-server.test.ts`, `emitters.test.ts` (mutated)         | static tokens in dev (NEEDS 805)                                                                             |
| B5  | Cross-tenant read of a statement                                                                | forced RLS in Postgres, token-bound tenant, read-only scope                                                                                                                                                                                    | Postgres RLS test with `SET ROLE axis_app`                 | none known                                                                                                   |
| B6  | Rewriting history: editing usage, deleting rows, changing a closed period                       | insert-only grants plus `forbid_mutation` triggers (also bind the owner); sealed-period insert trigger; hash-chained, signed seals; `verifySeal` detects out-of-band edits                                                                     | `ledger.test.ts` (trigger, tamper and signature tests)     | an owner who disables triggers is detected, not prevented; seal key is a dev HMAC (NEEDS 802)                |
| B7  | Quiet adjustment to hide fraud                                                                  | adjustments need a reason and an actor, an audit event is written first (fail closed), the original row stays                                                                                                                                  | `service.test.ts`                                          | the audit chain in the dev server is in memory (NEEDS 807)                                                   |
| B8  | Overflow / negative quantities                                                                  | bigint, +-(2^53-1) CHECK and validation, usage >= 0, exact `numeric` sums                                                                                                                                                                      | `core.test.ts`, property tests                             | none known                                                                                                   |
| B9  | Rounding drift siphons or creates value                                                         | single rounding rule per line, largest-remainder allocation, cumulative minor-unit rounding                                                                                                                                                    | property tests (`rating.test.ts`)                          | none known                                                                                                   |
| B10 | Live Stripe key used from a test or dev stack                                                   | constructor refuses anything but `sk_test_`/`rk_test_`; live-mode responses and events refused                                                                                                                                                 | `stripe.test.ts` (mutated)                                 | a test key can still reach real (test-mode) Stripe objects                                                   |
| B11 | Forged webhook                                                                                  | HMAC `t.payload`, constant-time compare, 300 s tolerance both ways, raw body only, duplicate event ids ignored                                                                                                                                 | `stripe.test.ts` (mutated)                                 | the dedupe store is in memory (NEEDS 804)                                                                    |
| B12 | Double invoice or double usage at the provider                                                  | idempotency key on every mutation, derived from stable ids; reconciliation reports duplicates                                                                                                                                                  | `stripe.test.ts`, `service.test.ts`                        | provider-side TTL of keys (24 h at Stripe)                                                                   |
| B13 | Secrets in logs or errors                                                                       | errors carry codes and short messages; a rejected key is never echoed; provider response bodies are not copied                                                                                                                                 | `stripe.test.ts`                                           | none known                                                                                                   |
| B14 | Billing outage stops agents (availability)                                                      | metering is off the decision path; the emitter raises, the runtime keeps going; the run log is the durable source and resending is idempotent                                                                                                  | `test_usage.py`                                            | usage is delayed until resent (NEEDS 803)                                                                    |
| B15 | Unbounded requests exhaust the service                                                          | body cap 4 MB, 20 000 events per post, 500 rows per entries read                                                                                                                                                                               | `dev-server.test.ts`                                       | no rate limit (dev surface)                                                                                  |
