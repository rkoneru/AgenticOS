# Registry and marketplace threat model (supply chain)

Scope: `services/registry`, `services/marketplace`. Assets: what runs in tenants (blueprints), publisher keys, tenant permissions and data,
the integrity of reviews and of installs. Attacker: malicious or compromised publisher, malicious tenant, malicious reviewer-adjacent insider, a
network or storage attacker who can read/modify stored records.

| #   | Threat                                               | Mitigation (tested)                                                                                                                                                                                             |
| --- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | Typosquatting (`payro1l-agent`, `acrne`, `adm1n`)    | `UNIQUE(normalized)` for names within a namespace and for namespaces; reserved words; folding of case, hyphens, `i l 1`, `o 0`, `rn m`, `vv w`, `3 e`                                                           |
| S2  | Dependency confusion (public name shadows a private) | references must be namespace-qualified; unqualified is refused, never searched; a public namespace may only depend on public ones; namespaces are single-tenant                                                 |
| S3  | Malicious blueprint                                  | ABL schema + lint, static capability scan, human review (critical never approvable, high acknowledged by id), recommended deny-by-default policy pack, and the Risk Kernel still gates every call               |
| S4  | Key compromise                                       | per-namespace keys with effective times; revoke as `compromised` distrusts everything the key signed; rotation without overlap; key rows only move NULL -> value                                                |
| S5  | Rollback / stale-version attack                      | resolve never falls back to an older version on verification failure; `notBelow` lock; updates to lower versions need an explicit flag; yank is final                                                           |
| S6  | TOCTOU between review and install                    | approval pinned to the content hash and re-verified at decision; install re-resolves, re-verifies, re-scans and re-diffs; the consent digest binds hash + additions; baseline change invalidates consent        |
| S7  | Republish after approval (swap content)              | versions are immutable (PK + trigger, no delete); a new version is a new review; only `approved[]` (hash pinned) is installable                                                                                 |
| S8  | Storage tampering / forged records                   | verify-on-read: canonical text, schema, hash, signature (strict base64), key window, provenance subject/lint reproduction; property test flips every character of every signed field                            |
| S9  | Forged provenance (signed but lying)                 | subject and ABL digest compared to recomputed values; lint counts and codes must be reproducible; foreign compiler / old compiler refused                                                                       |
| S10 | Reviewer collusion / self-approval                   | reviewer is staff, never the submitter, a tenant member or anyone who acted for the publisher; all decisions audited in the publisher's chain; separate credential kinds. Residual: two colluding staff (NEEDS) |
| S11 | Permission creep via updates                         | update diff is against the install's GRANT; widening needs fresh consent; narrowing takes least privilege                                                                                                       |
| S12 | IDOR / cross-tenant access                           | forced RLS; tenant from the credential only (spoofed `tenant_id` = 403); other tenants get 404 for private namespaces, installs, baselines; platform/catalog paths are explicit and tested in SQL               |
| S13 | Takedown evasion                                     | takedown is immediate for new installs/updates, yanks registry versions, flags existing installs (audited per tenant). Residual: running agents keep running until the tenant acts (NEEDS)                      |
| S14 | Secrets in blueprints                                | scan flags credential patterns as critical (auto-rejected)                                                                                                                                                      |
| S15 | Abuse (spam submissions, scraping, installs)         | sliding-window limits, stricter on submissions/installs, body cap, rate limit applies to anonymous catalog reads                                                                                                |
| S16 | Audit gaps                                           | every mutation writes ALLOW/DENY before and after; an unwritable decision is not performed (tested with a failing sink)                                                                                         |
| S17 | Billing manipulation through installs                | idempotency key per install id; installer tenant only as a hash; hook failure cannot fail installs; usage lands in the publisher's tenant ledger (payouts not implemented)                                      |

Not covered: a compromised registry operator with DB owner access (can rewrite rows; verification then fails for any record whose signature they cannot
forge, but they can delete data or alter `publishedAt`), no transparency log, publisher keys are held by publishers (no KMS), the clock is trusted.
| S7 | Publisher IP / unreviewed content exposed by listing a namespace | a version is public only when the marketplace released it (RLS on `registry_public_versions`, migration 0012); the review-time scan reads every model-visible text (tool descriptions, notice), folds Unicode/whitespace tricks, flags IPv6 literals and credentials in URLs; an install is re-checked after the write so a racing takedown flags it; publisher metering is once per (installer, listing) | transitive agent dependencies are not part of the consent (NEEDS #290) |
