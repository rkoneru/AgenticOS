# Phase 5 plan — Channels and voice

Goal: the same agent serves chat and voice across at least three channels, with transcripts in audit.

| #   | Component       | Location                                            | Coverage                                                 | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --- | --------------- | --------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A   | Channels        | `services/channels` (TS) + runtime `ChannelBackend` | 85% (signature verification, tenant routing, dedupe 95%) | channel abstraction (inbound normalize / outbound render / capabilities); adapters: web widget (HTTP+SSE), Slack, Teams, email, SMS, WhatsApp — each with real request-signature verification (Slack signing, Twilio, Meta HMAC, Teams JWT-shape), replay protection, per-tenant routing, and FAKE transports in tests (no real network/creds; NEEDS rows); unified end-user conversation state across channels (identity linking, tenant-scoped, Postgres with RLS via additive migration + ADR if needed); outbound messages are gated actions (kind "channel"); transcripts appended to audit |
| B   | Voice           | `services/voice` (TS) and/or `runtime/.../voice/`   | 85%                                                      | streaming STT -> agent -> TTS pipeline, barge-in (interrupt TTS on user speech), turn-taking/endpointing, provider adapters (STT/TTS) behind interfaces with deterministic fakes, SIP/WebRTC gateway interface + loopback fake (real SIP/WebRTC stack recorded in NEEDS), transcripts + consent/recording-notice, latency metrics per stage                                                                                                                                                                                                                                                      |
| C   | Integration e2e | `e2e/test_phase5_channels.py`, `make e2e-phase5`    | -                                                        | one agent, >=3 channels (web, Slack, SMS/email) + voice; conversation continuity across channels; outbound gated (DENY blocks send); transcripts in the audit chain; bad signatures / replays rejected; cross-tenant routing impossible                                                                                                                                                                                                                                                                                                                                                          |

Rules: every outbound message and tool use still passes the Risk Kernel; PHI/redaction apply to transcripts; NEEDS continues after the highest.
