# Phase 8 plan — Eval Hub integration

Goal: blueprint releases are blocked when evals regress; eval history is visible per version.

The ABL already declares `spec.evals.suites[{ref, threshold}]` (manifest `evals`); the frozen `/v1/evals/runs` POST exists (501 until now).

## Hub API (shared contract between components; owner: component A, additive OpenAPI 1.3.0 + ADR)

- `datasets`: versioned, immutable versions, tenant-scoped; cases `{id, input, expected?, tags, metadata}`; content hash per version; PHI flag (redact before persist).
- `suites`: `{ref (name@version), dataset_ref, graders[], pass_threshold, tolerance, required_for_release}`; graders = `deterministic` (exact / contains / regex / json-schema / numeric-tolerance / tool-call-sequence / policy-decision / cost-latency budget), `model` (rubric; judge model via ModelGateway), `human` (queue).
- `eval runs`: `{id, suite_ref, blueprint (name@version, content_hash), mode: ci|online|manual, status, scores{overall, per_grader, per_case}, case_results[], cost, started/finished, runner_id, provenance (runner version, model ids, seed)}` — append-only, hash-chained into the tenant audit chain (summary event), linked to the registry version.
- `baselines` per (blueprint name, suite): last released run; comparison `{delta, regression: bool, significance}` with a configurable tolerance; no hard-coded scores anywhere — scores come only from executed graders.
- `gates`: `POST /evals/gate {blueprint, suites}` -> `{allowed, reasons[], runs[]}`; registry release/publish-for-marketplace and `axis evals gate` call it; a missing, stale (blueprint hash mismatch) or failing run => blocked (fail closed).
- `online sampling`: `{blueprint, suite, rate, max_per_hour, redaction}`; sampled production runs graded asynchronously from audit/run-log rows; results never feed back into any decision path.
