and Postgres 16 all share the machine. Date of the numbers: 2026-10-09. Raw reports: `perf/results/loadtest-short.{json,md}`, `infra/dr/results/dr-drill.{json,md}`.
Verdicts are `Met`, `Not met` or `Not measured`. **Extrapolation is not a measurement**: a figure for a region, a cluster or a month is never derived here from a figure for this machine.

## Resource defects found by measuring (fixed, each with a failing-first test; ADR 0103)

| Defect                                                                                                                                                        | Evidence                                                              | Fix                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Run service kept ~5.2 MB per run forever (2.3 GB after ~2000 runs): three default httpx clients per run each loaded the CA bundle                             | RSS 2.29 GB -> 4.93 GB over 500 runs; test: 150 client trios +765 MiB | one shared SSL context (`axis_runtime._tls`); test requires < 120 MiB                                                             |
| Audit append retry storm: more callers on a chain meant fewer appends/s (8 callers 170/s vs 1 caller 271/s; the kernel could exhaust its 5 attempts and DENY) | audit bench                                                           | lock taken up front: 8 callers 264/s, 32 callers 234/s on the same machine state; test: 60 parallel appends with `maxAttempts: 1` |
| Gateway process crash when Postgres dropped an idle connection                                                                                                | chaos test 06                                                         | `pool.on("error")` in every service main                                                                                          |
| Kill-switches released by a kernel restart                                                                                                                    | chaos design review + test 03                                         | `FileKillSwitchStore` (ADR 0101)                                                                                                  |

## Not fixed, recorded

One audit chain per tenant serialises appends, which is the per-tenant gate capacity ceiling (NEEDS 3401). `RunService.runs` is never evicted and starting a run scans all of them (NEEDS 3402).
Kernel rate-limit and budget counters are in memory and keep one entry per distinct agent name (NEEDS 3406).

## How to reproduce

`make loadtest` (about 4 minutes), `make chaos` (about 2 minutes), `make dr-drill` (about 1 minute); runbooks in `docs/runbooks/{loadtest,chaos,dr}.md`.
